# CLAUDE.md — правила розробки MDS Connect

## 1. Що це

Внутрішня система **одного** салону M&D (записи, замовлення, зміни, виплати, склад, фінанси, Telegram-бот).
Не додавати мультитенантність, підписки, білінг, реєстрацію інших салонів.
Інтерфейс, тексти помилок і бот — **українською**. Коментарі в коді — мінімально, українською, лише там,
де логіку не видно з назв. Назви файлів і коду — англійською.

## 2. Стек

Python 3.11+ (CI 3.12), FastAPI, SQLAlchemy 2, Alembic, aiogram 3, ванільний JS PWA (без збірки),
SQLite (за замовчуванням) / PostgreSQL. Застосунки `apps/` — лише оболонки над веб-панеллю.

## 3. Команди

```bash
cd server
pip install -r requirements-dev.txt
python -m pytest                          # усі тести — обов'язково перед комітом
ruff check mds tests                      # лінтер
node --check mds/web/static/app.js        # синтаксис панелі
python -m mds init | run | serve | bot | start | migrate | backup
alembic revision --autogenerate -m "опис" # після зміни models.py (з каталогу server/)
```

## 4. Архітектура (коротко) — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)

- `mds/services/*` — **уся** бізнес-логіка і перевірка прав. `mds/api` і `mds/bot` — тонкі адаптери:
  запит → сервіс → відповідь. Правил у роутерах, боті й UI не дублювати.
- Сервісна функція: `(session, actor, ...)`, без `commit` — транзакцією керує `Database.session()`.
- Права — у сервісі (`actor.require(...)`, `_check_access`), не лише в UI.
- Помилки — `mds.errors.*`: ValidationError 422, Conflict 409, Forbidden 403, NotFound 404.
- Один процес (API + бот + фонові цикли) — одна репліка.

## 5. Канон — єдине джерело правди

- Бізнес-правила й рішення директора — [docs/CANON.md](docs/CANON.md). Гроші — [docs/FINANCE.md](docs/FINANCE.md).
- Пріоритет: CANON/FINANCE → цей файл → інші `docs/` → код і коментарі → `docs/ARCHIVE/` і `audit/` (історія).
- Якщо код суперечить канону — міняється код (з тестами), не канон. Канон змінює лише директор.
- Відкриті питання Q-1…Q-12 (CANON §2): діє «тимчасовий варіант»; не вирішувати самостійно, питати.
- `docs/` описують реалізований канон 0.3.0. Що ще не зроблено — позначено «не реалізовано» у відповідному документі.
  Стан до канону (11.11.2026) — `audit/21_CANON_COMPLIANCE.md` (знімок, не редагується).

## 6. Інваріанти — не порушувати

1. Гроші — `int` копійки; ставки — bp (`5000` = 50 %). Ніяких `float`/`Decimal` у розрахунках.
2. Формула поділу одна: `master = (P × master_rate_bp) // 10000`, `salon = A − master − M`
   ([FINANCE.md](docs/FINANCE.md) §2). Код — лише `services/finance.py::compute_split`.
3. `amount == master_earning + materials_cost + salon_earning` для кожного замовлення.
4. Знижки й матеріали — за рахунок салону; округлення — на користь салону; майстер ≥ 0.
5. Минулі замовлення не перераховуються; звіти беруть збережені суми (D-2).
6. `ledger`, `audit_log`, `orders` — лише додавання. Виправлення = сторно + новий запис + причина.
   Витрати — архів, не видалення.
7. Кожна зміна важливих даних пише `audit(...)` (було / стало / хто / причина).
8. Подвійні дії блокує БД: `_lock_master` перед перевіркою перетинів; атомарний `UPDATE … WHERE status IN …`;
   `UNIQUE(orders.appointment_id)`, `UNIQUE(payouts.shift_id)`; ключ ідемпотентності; `version` → 409 з поточним станом.
9. Час — лише `mds.clock.now()` (naive, час салону). Не `datetime.now()` у логіці.
10. Зміна `models.py` ⇒ нова міграція (тест `test_migrations_match_models`).
11. Telegram — лише через чергу `services/notifications.py`, не напряму з сервісів.
12. Панель: DOM лише через `h()`, без `innerHTML` з даними. Бот: `html.escape` для даних.
13. Лише дві ролі: `director`, `master`. Ролі `admin`, `materials_mode`, `share_bp`, списань з майстрів не повертати.
14. Без `print` у робочому коді — `logging` (CLI-команди в `__main__.py` — виняток).
15. Секрети — лише змінні `MDS_*`. Не логувати телефони, тексти повідомлень, ключі.

## 7. Як додавати функцію

1. Сервіс + тест у `tests/test_*.py` (фіксований час — фікстура `fixed_clock`, дані — `seed`).
   Гроші — тест на конкретні суми (приклади FINANCE §2).
2. Роутер у `mds/api/routers/` + тест у `tests/test_api.py` (і перевірка прав для обох ролей).
3. UI: `VIEWS.<name>` у `mds/web/static/app.js` + пункт у `NAV[роль]`. Бот (лише перегляд/підтвердження):
   обробник у `bot/staff.py` або `bot/handlers.py` + тест у `tests/test_bot.py` (`BotHarness`).
4. Якщо змінено `models.py` — міграція.
5. Оновити `docs/` (гроші — `FINANCE.md`; ендпоінти — `API.md`; таблиці — `DATABASE.md`) і `CHANGELOG.md`.

## 8. Процес змін

- Ніколи не пушити в `main`. Кожна зміна — окрема гілка + Pull Request.
- CI (`.github/workflows/ci.yml`) зелений: ruff + `node --check` + усі тести + UI-регресія (`ui-tests/`, Playwright).
- PR зливає лише людина (директор) після перегляду. Автоматичних змін без погодження немає.
- Зміни фінансових правил — лише за явним рішенням директора, записаним у `docs/CANON.md`.
- Великі задачі — фазами з зупинкою на погодження; звіт перед виправленням.
- Версії: пакетами; `__version__` у `server/mds/__init__.py` + `version` у `server/pyproject.toml` + розділ
  `## [X.Y.Z] — дата` першим у `CHANGELOG.md` (корінь; `test_version.py`). Тег і Release створює `release.yml`.

## 10. Не чіпати без окремого рішення директора

- `services/finance.py::compute_split` — лише разом із `docs/FINANCE.md` і тестами на суми.
- `services/orders.py::correct_order` — механізм сторно; не перетворювати на «редагування на місці».
- Міграції, що вже в `main`, не редагувати — лише нові. Не видаляти фінансові дані міграціями
  (застарілі колонки — лише після релізу, у якому їх перестали читати).
- Інструменти очищення (`wipe.py`, `demo_fop1.py`) — лише тестове середовище (D-8).
- Сайт салону — лише в гілці `website`; у `main` його немає. Публічного API для сайту немає.
- Клієнтські канали запису — лише через `bookings.create_appointment` з actor роллю `client` (антиспам).
- MDs Manager — лише читання через `/api/ext/v1` (D-5); жодних записів у Connect.
