# Звіт про реліз MDS Connect 0.3.0

## 1. Що в релізі

Канон MDS Connect 0.3.0 (рішення директора 11.11.2026, [docs/CANON.md](docs/CANON.md), [docs/FINANCE.md](docs/FINANCE.md)).
Повний опис — розділ `## [0.3.0] — 2026-11-12` у [CHANGELOG.md](CHANGELOG.md) (Змінено / Додано / Прибрано /
Виправлено / Міграції і оновлення). Коротко:

- Одна формула поділу: майстру 50 % від ціни до знижки, знижки й матеріали — за рахунок салону; старі замовлення
  не перераховуються (D-2).
- Статуси замовлень `completed / unpaid / cancelled / refunded`, сторно й повернення лише додаванням.
- Лише ролі «Директор» і «Майстер» (адміністратори стали директорами, D-4).
- Товари з бонусом майстру, єдиний журнал складу, сповіщення трьох рівнів, режим «Ми у відпустці».
- Безпека: PIN «Фінансів», журнал входів, автовихід 30 хв, блокування PIN бота в БД, CSP/HSTS, `MDS_ENV`.
- Бекапи: 30 днів, шифрування для Drive, Service Account (необов'язково), перевірка відновлення.
- Бот — без фінансового закриття замовлень; «Термінал» — вручну; SMS із Connect вимкнено.
- Read-only API для MDs Manager `/api/ext/v1` (ключ `X-API-Key` = `MDS_MANAGER_API_KEY`).
- Правки директора 0.2.2 (етапи A–F) — у складі релізу.

Обсяг відносно `main`: 15 комітів, 176 файлів (+11 714 / −1 919).

## 4. Команди: тег (вручну)

Тег ставиться на останній коміт гілки `release/0.3.0` (з цим звітом):

```bash
git fetch origin release/0.3.0
git checkout release/0.3.0
git pull --ff-only origin release/0.3.0
git log --oneline -1                      # перевірити, що це останній коміт гілки
git tag -a v0.3.0 -m "MDS Connect 0.3.0 — канон"
git push origin v0.3.0
```

Зливати в `main` — **звичайним merge commit** (не squash і не rebase), інакше коміт із тегом не потрапить у `main`.
Після злиття `.github/workflows/release.yml` побачить тег `v0.3.0` і створить GitHub Release з описом із CHANGELOG
(тег не перезаписується). Якщо Release уже створено вручну — workflow його пропустить.

## 5. Деплой на Railway (робить директор)

Railway збирає `main`, тож деплой = злиття PR `release/0.3.0` → `main`.

**До злиття**
1. «Налаштування → Створити копію зараз» і **завантажити копію на ПК** (відкат — лише з бекапу).
2. Variables: **прибрати** `MDS_WIPE_DATA` і `MDS_DEMO_FOP1`, якщо є (інакше сервер не стартує, D-8);
   `MDS_ENV` не задавати (типово `production`).
3. Перевірити, що задано `MDS_SECRET_KEY` (інакше після деплою всі увійдуть заново — не критично).
4. Необов'язково: `MDS_MANAGER_API_KEY` (довгий випадковий рядок) — лише коли MDs Manager готовий читати.
   `MDS_INTEGRATION_TOKEN` більше не використовується — можна видалити.
5. Volume `/data` змонтований, Replicas = 1.

**Після деплою** (1–3 хв, бот у цей час недоступний)
1. `GET https://<домен>/api/health` → `"version": "0.3.0"`.
2. Вхід директора; колишні адміністратори входять своїм логіном, тепер із правами директора.
3. «Фінанси»: суми минулих днів не змінилися (D-2); останні замовлення на місці.
4. Тестове закриття одного запису: майстру 50 % від ціни, «Салон» = сума − майстер − матеріали.
5. Бот: вхід PIN, перегляд записів; кнопки закриття замовлення немає.
6. Журнали Railway: без `ERROR` при старті; рядок «Резервна копія: …».
