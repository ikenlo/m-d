# Історія змін — MDS Connect

Формат: [Keep a Changelog](https://keepachangelog.com/uk/1.1.0/). Версії — [SemVer](https://semver.org/lang/uk/).
Версія в коді: `server/mds/__init__.py` (`__version__`) і `server/pyproject.toml`; розгорнуту версію
показує `GET /api/health`.

**Правило версій:** кожне оновлення сайту (злиття в `main`) — нова версія `0.1.1`, `0.1.2`, `0.1.3`…
У PR піднімається номер у коді й додається розділ `## [0.1.N] — дата`. Після злиття GitHub Actions
(`.github/workflows/release.yml`) сам створює тег `v0.1.N` і GitHub Release з цим описом та архівом коду.

## [0.1.11] — 2026-11-04

### Виправлено
- **XML-декларація ФОП 1 групи — правильна форма.** Раніше формувалась квартальна форма F0103309 (вона для 3 групи);
  тепер — річна **F0103407** («у якого податковий (звітний) період рік») і Додаток 1 **F0134107** (ЄСВ),
  за офіційними схемами ДПС з реєстру електронних форм (наказ Мінфіну № 578 у редакції № 57). Перевірка схемою в тестах.

## [0.1.0] — 2026-11-03

Перша контрольна версія. Система працює для одного салону M&D на Railway
(веб-панель PWA + Telegram-бот + сервер API). Повний звіт аудиту — [docs/AUDIT_v0.1.md](docs/AUDIT_v0.1.md).

### Що є у версії 0.1
- **Акаунти й ролі:** директор, адміністратор, майстри; вхід за логіном/паролем, блокування після
  невдалих спроб, вихід з усіх пристроїв при зміні пароля.
- **Календар:** записи, перенесення, скасування, підтвердження; захист від подвійних записів;
  графік роботи майстрів по датах; блок непідтверджених записів з діями
  «Підтвердити / Інший час / Час зайнятий» (клієнт отримує варіанти в боті).
- **Закриття замовлення** у кілька натискань: фактична сума, готівка/картка, матеріали зі складу,
  уточнення імені та прізвища клієнта.
- **Фінанси:** поділ 50/50 або індивідуальний відсоток, три режими обліку матеріалів;
  закриття зміни зі звітом; каса після зміни (майстер бере заробіток із готівки, решту директор
  доплачує на картку); виплати; витрати (оренда, комунальні, реклама, інше, закупівля);
  фінансова панель: виручка, частки, валовий і чистий прибуток, розрізи за днями/майстрами/послугами.
- **Журнали:** фінансовий журнал лише на додавання (виправлення = сторно + нове проведення),
  історія змін «було/стало/хто/причина».
- **Склад:** матеріали й фарби за тонами, туби/грами, прихід, інвентаризація, списання,
  автоматичне списання при закритті замовлення, мінімальні залишки.
- **Telegram-бот:** запис за деревом послуг (Чоловічі/Жіночі → тип → вид), швидкий запис
  (передзвоніть), вільний час, ціни, контакти, улюблений майстер після 3 візитів;
  розділ «Для майстрів» (код салону + особистий PIN): записи, закриття замовлень, зміна, заробіток.
- **Надійність:** щоденні резервні копії з перевіркою цілісності, черга сповіщень (outbox),
  кнопка «Повідомити про помилку» директору в Telegram.
- **Розгортання:** Dockerfile + railway.json, автоматичні міграції Alembic (0001–0010) при старті.

### Виправлено під час аудиту 0.1
- Безпека: майстер через `POST /api/clients` міг дізнатися ім'я будь-якого клієнта за номером і
  перезаписати його нотатки без запису в журнал. Тепер це дія директора/адміністратора з аудитом.
- Безпека: запит чужого замовлення повертав 422 замість 403.
- Бот: команда «Сьогодні» ламалася, якщо в імені клієнта були символи `<`/`>` (дані тепер екрануються).
- Бот: повторне натискання запропонованого часу після «Час зайнятий» створювало кілька записів.
- API: завеликі числа (сума, ціна, кількість) давали помилку сервера 500 — тепер зрозуміла помилка 422.
- Склад: створення матеріалу без ціни, порожні поля, від'ємний мінімум, нескінченні кількості.
- Резервні копії: з'єднання з базою тепер закриваються після кожної копії.
- Веб-панель: програма запускається, навіть якщо браузер блокує локальне сховище.
- `GET /api/health` повертає версію.

### Додано тести
- `test_permissions.py`: матриця прав (майстер не бачить і не змінює чужого, не має функцій директора).
- `test_invariants.py`: фінансові інваріанти на випадкових даних (поділ, журнал, дашборд, баланси).
- `test_edge_inputs.py`: граничні значення на вході — жодних помилок 500.
