# 16 — Production readiness (v1.0) recommendations

**Production-ready today? No.** The system is functionally rich and well tested for its *current* rules. It is not ready because (1) the money rules contradict the approved canon, (2) there are three HIGH security issues, and (3) backups lack encryption and a proven restore.

## Must-do before v1.0
1. Canon financial model (2.1) + statuses unpaid/refunded (2.17) + reports (2.11). Money correctness is the product.
2. Remove legacy: modes, Admin, utility deductions (2.2), with a role migration plan (C-4).
3. Security: bot PIN lockout and staff-code change (S-2); remove destructive env switches from `start` (S-3); rotate the leaked Manager secrets (S-1); CSP; IP throttle on login; pinned deps with hashes.
4. Version lock on orders, expenses and payouts (two directors editing at once) and idempotency on payouts and expenses.
5. Backups: encrypted remote, age-based 30-day retention, alert on local failure, **rehearsed restore** (script + CI job), third copy.
6. Auto-logout (decide scope, C-22), login journal.
7. Critical alerts: salon < 0, negative balance, and an alert when the outbox drops messages.
8. Role × endpoint matrix tests.

## Should-do
Products and bonus (2.3), vacation mode (2.5), exports (PDF/Excel), finance PIN (if still wanted with 2FA), UI per §0.17, Mermaid logic view (after 2.1), `app.js` modularisation, ledger indexes.

## Safe to postpone
FEFO/batches, POS auto (already exists), local LLM (only the abstraction is needed now), VPS migration (after 1.0 if Railway is stable), native apps, Manager hourly sync extras.
