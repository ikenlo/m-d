# Застосунки MDS Connect: Android (.apk) і Windows (.exe)

Обидва застосунки — «вікно» до веб-панелі салону (`https://m-d-production.up.railway.app`).
Уся логіка і дані — на сервері, тому:
- оновлення сайту одразу видно в застосунках, перевстановлювати не треба;
- права, розрахунки, журнали — ті самі, що й у браузері;
- перевипускати застосунок потрібно лише при зміні самої оболонки (іконка, назва, адреса сервера).

| | Android | Windows |
|---|---|---|
| Код | `apps/android` (Java, WebView, без сторонніх бібліотек) | `apps/windows` (Electron) |
| Файл | `MDS-Connect-0.1.0.apk` (~60 КБ) | `MDS-Connect-Setup-0.1.0.exe` (інсталятор) |
| Мінімум | Android 7.0 | Windows 10/11 x64 |

Що вміють обидва: вхід зберігається між запусками; без інтернету — екран «Немає з'єднання» з кнопкою
«Спробувати ще»; посилання на телефон, Telegram, Google, карти відкриваються у відповідних застосунках
або браузері; вибір файлу (знімок екрана для баг-репорту). Windows: одна копія програми, запам'ятовує
розмір вікна, F5 — оновити.

## Встановлення

**Android:** надішліть файл `.apk` майстру (напр. у Telegram) → відкрити → дозволити «Встановлення з
невідомих джерел» для Telegram/браузера → «Встановити». На робочому столі з'явиться «MDS Connect».

**Windows:** запустити `MDS-Connect-Setup-0.1.0.exe` → якщо Windows попередить «Невідомий видавець»
(SmartScreen): «Докладніше» → «Однаково запустити» → далі як звичайна програма. Ярлик на робочому столі
і в меню «Пуск». (Попередження зникне лише з платним сертифікатом підпису коду — для одного салону не потрібно.)

## Як випустити нову версію

1. Змінити `versionCode`/`versionName` у `apps/android/app/build.gradle` і `version` у `apps/windows/package.json`
   (та назви файлів у `.github/workflows/apps.yml`).
2. PR → GitHub Actions «Apps» збирає обидва файли і запускає APK на емуляторі Android (перевіряє, що
   відкривається сторінка входу).
3. Після злиття: GitHub → Actions → Apps → Run workflow → `release` = так. З'явиться GitHub Release
   з `.apk` і `.exe` (репозиторій приватний — завантажує власник і пересилає персоналу).

## Підпис Android (один раз, до відкриття)

Android дозволяє оновити застосунок лише файлом з тим самим підписом. Ключ зберігається в секретах GitHub:
- `ANDROID_KEYSTORE_BASE64` — файл ключа (`.jks`) у base64;
- `ANDROID_KEYSTORE_PASSWORD` — пароль (ключ `mds`, пароль ключа той самий).

GitHub → Settings → Secrets and variables → Actions → New repository secret. **Збережіть копію ключа
й пароля окремо** (напр. у сейфі паролів): без нього оновлення встановлюватиметься лише після видалення
старої версії (дані не губляться — вони на сервері, треба лише увійти знову).
Поки секретів немає, CI підписує тестовим ключем і пише попередження.

## Локальна збірка (для розробника)

```bash
# Android: потрібні JDK 17+, Gradle 8.9+, Android SDK (platforms;android-34, build-tools;34.0.0)
cd apps/android && echo "sdk.dir=/шлях/до/android-sdk" > local.properties
gradle assembleRelease            # -PappUrl=https://... — інша адреса сервера
# Windows (збірка .exe — на Windows або в CI)
cd apps/windows && npm ci && npm start            # MDS_APP_URL=http://localhost:8000 npm start — локальний сервер
npm run dist
```
