# Checkbox (ПРРО) — фіскальні чеки і друк

Connect створює фіскальний чек у [Checkbox](https://checkbox.ua) для кожного **оплаченого** замовлення і передає
його на чековий принтер через планшет (застосунок MDS для Android). Грошей це не змінює: закриття, повернення
й звіти працюють так само, з Checkbox або без нього. Сервіс — `server/mds/services/checkbox.py`.

Контракт — офіційна OpenAPI-специфікація Checkbox **2.112.0** (`https://api.checkbox.ua/api/openapi.json`,
[ReDoc](https://api.checkbox.ua/api/redoc), [Wiki](https://wiki.checkbox.ua/uk/api/specification)).
Перевірено тестами з імітацією HTTP (`respx`); перед роботою з реальними чеками — перевірка на тестовій касі (нижче).

## Налаштування

**Ключі касира — лише змінні середовища** (Railway → Variables), не база, не браузер, не бекапи (CLAUDE.md, інв. 15):

| Змінна | Що це |
|---|---|
| `MDS_CHECKBOX_LOGIN`, `MDS_CHECKBOX_PASSWORD` | логін і пароль касира Checkbox (`POST /api/v1/cashier/signin`) |
| `MDS_CHECKBOX_LICENSE_KEY` | ключ ліцензії каси (`X-License-Key`, потрібен для відкриття зміни) |
| `MDS_CHECKBOX_API_URL` | за замовчуванням `https://api.checkbox.ua`; для тестової каси — адреса з кабінету Checkbox |

**Директор → «Налаштування → Checkbox (ПРРО)»** (`GET/PATCH /api/settings/checkbox`, лише директор; у загальному
`PUT /api/settings` ці ключі не змінюються):

| Поле | Ключ у `settings` | За замовчуванням |
|---|---|---|
| Фіскалізувати оплачені замовлення | `checkbox_enabled` | вимкнено (увімкнути можна лише із заданими ключами) |
| Чековий принтер | `checkbox_printer_type` | `none` / `wifi` / `bluetooth` |
| IP і порт Wi-Fi принтера | `checkbox_printer_ip`, `checkbox_printer_port` | — , 9100 (IP лише з локальної мережі) |
| Bluetooth-принтер | `checkbox_printer_bt_name` | порожньо — перший спарений принтер |
| Ширина стрічки | `checkbox_printer_width` | 32 (58 мм); 42 / 48 — 80 мм |
| Кодова сторінка | `checkbox_printer_codepage` | `cp1251` (уся українська абетка); `cp866` — без І, і, Ґ, ґ (замінюються на I, i, Г, г) |

Кнопки: «Перевірити зв'язок» (вхід касира + стан зміни), «Відкрити / Закрити зміну ПРРО», «Тестовий друк»
(кирилиця — щоб підібрати кодову сторінку). Видно кількість чеків у черзі й з помилкою.

## Як створюється чек

1. Після закриття оплаченого замовлення (готівка, картка, POS-термінал, «Закрити вручну», «Клієнт оплатив пізніше»)
   панель викликає `POST /api/orders/{id}/fiscalize`. Неоплачені й нульові замовлення чека не мають.
2. Сервер створює запис у черзі `fiscal_receipts` (`pending`) з **власним UUID** — він же `id` чека в Checkbox,
   тож повтор після обриву не створить дубля; `orders.fiscal_receipt_id` = цей UUID. Повторний виклик повертає
   той самий чек (для повторного друку — кнопка «Друкувати чек» у картці замовлення).
3. Поза транзакцією БД: вхід касира → якщо зміни немає, вона відкривається з автозакриттям о **23:50** (Z-звіт
   робить Checkbox) → `POST /api/v1/receipts/sell`:
   - рядок послуги — фактично сплачена сума `A`, рядки товарів — ціна продажу × кількість (`quantity` у тисячних);
   - оплата: `cash` → `CASH`, `card` / `transfer` → `CASHLESS` («Картка» / «Переказ»); для оплати POS-терміналом
     додаються RRN, код авторизації й маска картки.
4. Відповідь:
   - **200** `done` — фіскальний номер, посилання на чек у податковій і `print_base64` (ESC/POS для принтера);
   - **202** `pending`, «Чек буде створено пізніше» — Checkbox недоступний (мережа, таймаут, 5xx). Замовлення вже
     закрите; фоновий процес повторює щохвилини (до 12 спроб), той самий UUID;
   - **200** `error` — Checkbox відмовив (дані, ключі); без автоповтору, видно в налаштуваннях.
   - 400 `checkbox_disabled` — фіскалізацію вимкнено; 409 — замовлення неоплачене або нульове.
5. Повернення замовлення (`POST /api/orders/{id}/refund`), якщо був чек продажу, ставить у чергу **чек повернення**
   (`is_return`, `related_receipt_id` = чек продажу) — він створюється фоновим процесом.

Кожен крок — у `audit_log` (`fiscal_receipt`: `enqueue`, `done`; налаштування — `checkbox`).

## Друк

Checkbox віддає чек звичайним текстом (`GET /api/v1/receipts/{id}/text?width=…`). Сервер додає команди ESC/POS:
`ESC @` (скидання), `ESC t n` (кодова сторінка: Windows-1251 = 46, CP866 = 17), текст, подача, `GS V B 0` (обрізання),
символи, яких немає в кодовій сторінці (тире, ₴, у CP866 — І/Ґ), замінюються на найближчі, а не на «?»,
і повертає Base64. Друкує **лише планшет** у застосунку MDS — сервер у хмарі принтера не бачить:

- `window.MDSAndroid.printWifi(ip, port, base64)` — TCP на принтер (лише адреса локальної мережі: 10.x, 172.16–31.x, 192.168.x);
- `window.MDSAndroid.printBluetooth(base64, deviceName)` — спарений принтер (SPP); без назви — перший спарений принтер;
  на Android 12+ застосунок попросить дозвіл «Пристрої поблизу» (BLUETOOTH_CONNECT);
- результат — `window.mdsPrintResult(ok, message)` → повідомлення в панелі.

Без застосунку (браузер, телефон майстра): «Чек фіскалізовано. Друк — із планшета в застосунку MDS»; принтер не
налаштовано: «Чек фіскалізовано, але принтер не налаштовано». Чек усе одно створено в Checkbox і податковій.

## Перевірка на обладнанні (перед першими реальними чеками)

Емуляція (нижче) перевіряє код Connect; ці кроки — лише з реальною касою, планшетом і принтером. Загальний список
обладнання — [ROADMAP.md](ROADMAP.md), «Перевірка обладнання (Hardware Integration Checklist)».

1. **Тестова каса Checkbox.** У кабінеті Checkbox — тестова каса й касир. На Railway: `MDS_CHECKBOX_API_URL`
   (тестова адреса з кабінету), `MDS_CHECKBOX_LOGIN`, `_PASSWORD`, `_LICENSE_KEY`. «Налаштування → Checkbox (ПРРО)» →
   «Перевірити зв'язок» → «Відкрити зміну ПРРО».
2. **Справжній макет чека.** Закрити замовлення готівкою, карткою (POS-термінал і вручну) і з товаром; повернути одне.
   У кабінеті Checkbox звірити: суми, CASH/CASHLESS, назви послуг і товарів, кількість, RRN для оплати терміналом,
   чек повернення з посиланням на чек продажу.
3. **Податки.** З бухгалтером: чи потрібні ставки (`tax`) у рядках чека (зараз не передаються) і коди товарів.
4. **Планшет.** Встановити APK 0.1.11 (з `printWifi` / `printBluetooth`), відкрити MDS у застосунку.
5. **Принтер Wi-Fi.** Статична IP у мережі салону, порт 9100 → «Тестовий друк»: кирилиця (І, Ї, Є, Ґ) читається,
   рядки не переносяться (ширина 32 для 58 мм, 42/48 для 80 мм), стрічка обрізається. Якщо ні — змінити кодову
   сторінку або ширину й повторити.
6. **Принтер Bluetooth.** Спарити в налаштуваннях Android, вказати назву → «Тестовий друк»; на Android 12+ дозволити
   «Пристрої поблизу».
7. **Збої.** Вимкнути інтернет на сервері/Checkbox → замовлення закривається, «Чек буде створено пізніше», після
   відновлення чек з'являється (черга); вимкнений принтер → повідомлення, «Друкувати чек» у замовленні після ввімкнення.
8. **Зміна.** Перевірити автозакриття о 23:50 (Z-звіт у кабінеті) і кнопку «Закрити зміну ПРРО».
9. **Робоча каса.** Змінні робочого касира, «Фіскалізувати» — увімкнути рішенням директора; запис у CHANGELOG.

## Обмеження

- Виправлення суми вже фіскалізованого замовлення («Виправити замовлення») чек не змінює — потрібне повернення
  і новий продаж (окреме рішення).
- Чек повернення — на всю суму чека продажу.
- Офлайн-режим Checkbox не використовується: без зв'язку чеки чекають у черзі Connect.

## Емуляція без каси і принтера

- `server/scripts/fake_checkbox.py` — емулятор API Checkbox (HTTP): вхід, зміна, чеки, текст чека, наближений до
  макета Checkbox, з позначкою «ЕМУЛЯЦІЯ — НЕ ФІСКАЛЬНИЙ». Фіскальних чеків не створює.
- `server/scripts/fake_printer.py` — емулятор мережевого чекового принтера (TCP 9100): розбирає ESC/POS
  (`ESC @`, `ESC t n`, `GS V`), декодує кодову сторінку й зберігає кожен чек як `.txt` і `.html` (вигляд стрічки).

```bash
cd server
python scripts/fake_checkbox.py --port 8779 &
python scripts/fake_printer.py --port 9100 --out /tmp/receipts &
MDS_ENV=test MDS_CHECKBOX_API_URL=http://127.0.0.1:8779 MDS_CHECKBOX_LOGIN=x MDS_CHECKBOX_PASSWORD=x \
  MDS_CHECKBOX_LICENSE_KEY=x python -m mds serve
```

Справжній макет чека формує Checkbox; емулятор перевіряє весь шлях Connect → чек → ESC/POS → принтер.

- `server/tests/test_checkbox.py` — `respx`: контракт запиту (CASH/CASHLESS, копійки, кількість у тисячних),
  ESC/POS, автовідкриття зміни, ідемпотентність, 202 і повтор, обрив після створення (без дубля), відмова, ліміт
  спроб, права, неоплачені, повернення через API, налаштування, зв'язок і зміна, секрети не потрапляють у відповіді.
- `server/tests/test_receipt_emulation.py` — ESC/POS Connect → розбір емулятором принтера дає той самий текст
  (cp1251 і cp866 із заміною літер, без «?»); повний ланцюжок з емулятором Checkbox.
- `ui-tests/receipt_e2e.js` — Playwright з обома емуляторами: директор налаштовує Checkbox і Wi-Fi принтер, закриває
  замовлення «Готівка + товар» і «Картка»; міст `MDSAndroid.printWifi` емулюється в Node (ті самі байти по TCP);
  знімки надрукованих чеків — `ui-tests/out/receipt-cash.png`, `receipt-card.png`.
- `ui-tests/checkbox.js` — Playwright з макетом Checkbox і підміненим `MDSAndroid`: налаштування, «Перевірити
  зв'язок», тестовий друк, закриття замовлення → чек CASH → ESC/POS на принтер, повторний друк без нового чека.
