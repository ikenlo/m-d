# MDS Connect — повний опис стану проєкту (для ШІ-помічника)

> Цей документ — стислий, але повний опис того, що вже зроблено, як це влаштовано, що ще не зроблено
> і яких правил треба дотримуватись. Дата: 4 листопада 2026. Версія коду: 0.1.6 (фіскалізація — у PR, очікує погодження) (див. CHANGELOG.md).

## 1. Що це за проєкт

**MDS Connect** — внутрішня система **одного** beauty-салону **M&D** (Нові Петрівці, Україна). Це **не SaaS**:
немає мультитенантності, підписок, білінгу, реєстрації інших салонів — і додавати їх не треба.
Мова інтерфейсу, повідомлень, помилок і бота — **українська**. Коментарі в коді — українською.

Користувачі:
- **Директор** (Маргарита) — повний доступ: фінанси, персонал, налаштування, виправлення, виплати.
- **Адміністратор** — записи, клієнти, графік, склад (без фінансів директора).
- **Майстри** — свої записи, закриття замовлень, своя зміна, свій заробіток.
- **Клієнти** — лише через Telegram-бот (запис, ціни, вільний час, контакти).

Робоча адреса: `https://m-d-production.up.railway.app` (Railway, автодеплой з гілки `main` GitHub-репозиторію `ikenlo/m-d`).
Салон ще не працює з реальними клієнтами — відкриття планується **на початку 2027 року**; зараз дані тестові.

## 2. Технології та архітектура

| Частина | Технології |
|---|---|
| Сервер | Python 3.12, FastAPI, SQLAlchemy 2, Alembic (міграції 0001–0011), SQLite (WAL, foreign keys) на диску Railway; PostgreSQL підтримується через `MDS_DATABASE_URL` |
| Авторизація | Логін/пароль (scrypt), JWT HS256 з `token_version` (вихід з усіх пристроїв при зміні пароля), блокування після невдалих спроб |
| Веб-панель | Ванільний JS без збірки (`server/mds/web/static/app.js`), PWA (service worker, іконки), світла/темна тема |
| Telegram-бот | aiogram 3, long polling, у тому ж процесі, що й API; сповіщення — через чергу (outbox) |
| Застосунки | Android: Java + WebView (`apps/android`); Windows: Electron + інсталятор NSIS (`apps/windows`) — обидва лише відкривають веб-панель |
| CI | GitHub Actions: `ci.yml` (ruff, перевірка JS, pytest), `apps.yml` (збірка APK + запуск на емуляторі, збірка EXE, ручний Release) |
| Деплой | Dockerfile + `railway.json`; при старті `python -m mds start`: міграції, створення директора з `MDS_DIRECTOR_*`, завантаження каталогу послуг, API + бот + фонові задачі |

Шари коду (`server/mds/`):
- `services/*` — **уся** бізнес-логіка і перевірка прав. Функції мають вигляд `(session, actor, ...)` і не роблять `commit`
  (транзакцією керує `Database.session()`).
- `api/routers/*` — лише перетворюють HTTP-запит → виклик сервісу → відповідь.
- `bot/*` — обробники Telegram (`handlers.py` — клієнти, `staff.py` — розділ «Для майстрів»), теж лише викликають сервіси.
- `models.py` — моделі БД; `migrations/versions/` — міграції Alembic.
- Помилки — `mds.errors.*`: ValidationError 422, Conflict 409, Forbidden 403, NotFound 404.
- Час — тільки через `mds.clock.now()` (локальний час Києва, naive datetime).

## 3. Фінансові правила (важливо)

- Гроші — **цілі копійки** (`int`), відсотки — **bp** (`5000` = 50%). Ніякого `float` у розрахунках.
- Для кожного замовлення: `сума = частка майстра + матеріали + частка салону`.
- Формула поділу — лише в `services/finance.py::compute_split`. Стандарт — майстру 50%, відсоток налаштовується для кожного майстра.
  Режими обліку матеріалів: `salon` (за замовч., матеріали зменшують частку салону), `master` (матеріали платить майстер), `split` (пропорційно).
- Фінансовий журнал (`ledger`) — **лише додавання**. Виправлення директором = сторно + нове проведення (`orders.correct_order`), з причиною.
- Кожна важлива зміна пише `audit(...)` (було / стало / хто / причина).
- **Каса після зміни:** майстер забирає свій заробіток із готівки в касі; якщо готівки менше — директор доплачує решту на картку;
  якщо більше — звіт показує, скільки лишити в касі.
- Способи оплати в інтерфейсі: **готівка, картка** («переказ» прибрано, але старі записи з ним підтримуються).
- Детально — `docs/FINANCE.md`.

## 4. Що вже реалізовано

### 4.1. Веб-панель (телефон і комп'ютер)
- **Вхід** у стилі M&D (темно-зелений/золотий), збереження входу, захист від підбору пароля.
- **Огляд (директор):** виручка, чистий і валовий прибуток, середній чек з порівнянням з попереднім періодом;
  «куди йдуть гроші» (частки майстрів, матеріали, оренда, комунальні, реклама, інше); зарплата майстрів
  (нараховано / виплачено / борг); оплати клієнтів (готівка / картка); виручка по днях; таблиці по майстрах і послугах.
  **Аналітика і прогноз:** прогноз виручки місяця (більше з «за темпом» і «факт + записи наперед»), прогноз чистого прибутку,
  середній чек по майстрах, нові / повторні клієнти, середня виручка по днях тижня. Періоди: день, тиждень, місяць, рік, довільний.
- **Календар:** записи по майстрах і днях, створення, перенесення, скасування (з причиною), «клієнт прийшов», «не прийшов».
  Захист від подвійних записів на той самий час (блокування на рівні БД).
- **Непідтверджені записи** (з бота) — блок угорі головної: «Підтвердити», «Інший час» (бот пропонує клієнту новий час,
  клієнт приймає кнопкою), «Зайнято» (бот сам пропонує найближчі вільні години).
- **Закриття замовлення** у кілька натискань: фактична сума, готівка/картка, матеріали зі складу, **ім'я та прізвище клієнта**
  (щоб збирати базу; зміна імені пишеться в журнал). Захист від подвійного закриття (idempotency key, UNIQUE).
- **Зміни й виплати:** відкриття/закриття зміни, звіт зміни (клієнти, послуги, скасування, виручка, заробіток, каса),
  підтвердження виплати директором, аванси/інші виплати.
- **Замовлення:** список, деталі, виправлення директором з причиною (історія змін видно).
- **Витрати:** оренда, комунальні, реклама, закупівля матеріалів, інше; редагування/видалення з причиною.
- **Клієнти:** пошук, картка з історією візитів, улюблений майстер (після 3 візитів). Майстер бачить лише своїх клієнтів.
- **Склад:** матеріали й фарби за тонами (лінійка → тон), облік у г/мл/шт і упаковках (туба 60 г тощо),
  прихід (з можливістю одразу записати витрату), інвентаризація, списання з причиною, автосписання при закритті замовлення,
  мінімальні залишки («закінчується»), вартість залишку, рух складу.
- **Графік роботи:** сітка-календар на 4 тижні для кожного майстра — квадратик = день, зелений з ✓ — робочий;
  одне натискання перемикає робочий/вихідний; режим «Години» — змінити години дня; «Копіювати тиждень»;
  тижневий шаблон майстра задається в «Персоналі», графік салону — в налаштуваннях.
- **Персонал:** майстри/адміністратори, відсоток, режим матеріалів, послуги майстра (згруповані за розділами), тижневий графік,
  PIN для бота, скидання пароля.
- **Послуги:** дерево «Чоловічі / Жіночі → тип → вид», ціни «від», тривалість (клієнтам у боті тривалість не показується); 42 послуги з прайсу салону.
- **Журнал:** стрічка подій простими словами по днях («Олена закрила замовлення — 650 ₴, картка»), «було → стало», причини,
  фільтри (гроші, записи, клієнти, склад, персонал), період, пошук; технічний фінансовий журнал — у згорнутому блоці.
- **Налаштування:** назва, відсоток за замовчуванням, режим матеріалів, крок слотів, запис наперед, автопідтвердження з бота,
  «майстер бере з каси», поріг улюбленого майстра, код для майстрів у боті, адреса/телефон/Instagram, графік салону,
  нагадування клієнтам (вкл/викл), **резервні копії і Google Drive**.
- **Кнопка «Повідомити про помилку»** — текст + знімок екрана + технічні деталі директору в Telegram.
- **Мобільна версія:** закріплена шапка, нижні вкладки, кнопка «‹ Назад» на сторінках з меню «Ще», таблиці як картки,
  без масштабування, клавіатура iPhone не перекриває форми.

### 4.2. Telegram-бот
**Для клієнтів (меню):** «Записатися» (розділ → тип → вид → майстер з найближчим вільним часом / «будь-хто» → день → час →
номер телефону контактом), «⚡ Швидкий запис» (заявка «передзвоніть»), «Послуги та ціни», «🕐 Вільний час», «📍 Контакти»,
«👩‍🎨 Для майстрів». Улюблений майстер пропонується першим. Клієнт може перенести/скасувати свій запис.
**Нагадування:** після першого запису бот питає згоду; нагадує **за добу і за 2 години** (лише підтвердженим записам),
у нагадуванні кнопки «Перенести / Скасувати / Більше не нагадувати», `/remind` — увімкнути знову.

**Для майстрів і директора** (код салону + особистий PIN, блокування після невдалих спроб): мої записи, новий запис,
закриття замовлення (сума, ім'я клієнта, готівка/картка), «Зайнято» / «Інший час» для непідтверджених, моя зміна і звіт,
мій заробіток; директор — фінанси, виплати, заявки «передзвоніть». Сповіщення про нові записи приходять кожному майстру особисто.

### 4.3. Надійність і безпека
- Права перевіряються на сервері (тест-матриця `test_permissions.py`); майстер бачить лише своє.
- Резервні копії: при старті і **кожні 6 годин**, перевірка цілісності, зберігаються локально (40 копій) і — після підключення —
  **у Google Drive** (папка «MDS Connect — резервні копії», доступ лише `drive.file`, 180 копій, помилка → повідомлення директору).
- Журнали лише на додавання, захист від подвійних записів/оплат/закриттів, екранування даних у боті (HTML), DOM у панелі
  лише через `h()` (без `innerHTML` з даними користувача), заголовки безпеки, обмеження на завеликі числа (422 замість 500).
- Аудит версії 0.1 — `docs/AUDIT_v0.1.md`.

### 4.4. Застосунки
- **Android (.apk, ~60 КБ)** і **Windows (.exe, інсталятор)** — оболонки, що відкривають веб-панель: вхід зберігається,
  без інтернету — екран «Немає з'єднання» з автоповтором, зовнішні посилання (телефон, Telegram, Google) — у браузері/застосунках,
  вибір файлу для баг-репорту. Збірка — GitHub Actions; інструкції — `docs/APPS.md`.
- Веб-панель має поліфіл для старих WebView (Android 7–11 без оновлень).
- **iOS:** окремого застосунку немає — використовується PWA («На екран Додому» у Safari).

### 4.5. Тести
114 автоматичних тестів (pytest): фінанси на конкретних сумах, інваріанти на випадкових даних, бронювання і конкуренція,
замовлення і каса, права доступу, граничні значення, бот (справжній диспетчер aiogram з імітацією Telegram), склад і графік,
Google Drive (імітація Google), нагадування, аналітика, журнал, міграції = моделі.
Перевірки перед кожним злиттям: `ruff check mds tests`, `node --check app.js`, `python -m pytest` (CI має бути зеленим).

| Тег `v0.1` | Коміт «Release v0.1» є в `main`; тег на GitHub треба поставити вручну (Releases → новий реліз, тег `v0.1`) |
| Перед відкриттям | Змінити стартовий пароль директора, код «Для майстрів» (`0000`), задати майстрам особисті PIN, очистити тестові дані (лише з окремого погодження директора) |
| Від'ємний заробіток | У режимах матеріалів `master`/`split` заробіток майстра може стати від'ємним, якщо матеріали дорожчі за частку. Потрібне рішення директора: лишити чи обмежувати нулем |
| Перерва між записами | Не реалізовано (напр. 10–15 хв на прибирання між клієнтами) — питання до директора |
| Експорт в Excel | Відкладено — зробити, коли директор попросить |
| Безпека (дрібне) | Немає Content-Security-Policy; токен у `localStorage`; версії залежностей задані діапазонами (не зафіксовані); стан діалогів бота і лічильник PIN — у пам'яті (скидаються при перезапуску) |
| Інше з плану | Знижки/сертифікати, двофакторна авторизація директора — `docs/ROADMAP.md` |

## 6. Як допомагати з цим проєктом (правила)

1. Не додавати мультитенантність, підписки, білінг — система для одного салону.
2. Бізнес-логіку — лише в `services/*`; роутери і бот — тонкі. Не дублювати правила в UI.
3. Гроші — копійки (`int`), відсотки — bp; формула — лише `compute_split`; журнал не редагується, тільки сторно.
4. Зміна `models.py` ⇒ нова міграція Alembic (інакше тест `test_migrations_match_models` впаде).
5. Повідомлення в Telegram — лише через чергу `services/notifications.py`.
6. Веб-панель: DOM лише через `h()`; бот: `html.escape` для даних користувачів.
7. Час — `mds.clock.now()`, не `datetime.now()`.
8. Кожна зміна — окрема гілка + Pull Request; CI має бути зеленим; зливає людина (директор дозволила оновлювати сайт після зеленого CI).
9. Зміни фінансових правил — лише за явним запитом директора і з тестами на конкретні суми.
10. Після змін у `app.js`/`style.css` — підняти версію кешу `CACHE` у `server/mds/web/static/sw.js`.
11. Нова функція: сервіс + тест → роутер + тест API → UI (`VIEWS.<name>` і пункт у `NAV[роль]`) / бот + тест → документація в `docs/`.

## 6а. Версії

Поточна версія — у `server/mds/__init__.py` і `GET /api/health`. Кожне оновлення сайту — нова версія `0.1.1`, `0.1.2`…
з розділом у `CHANGELOG.md`; після злиття в `main` GitHub Actions (`release.yml`) сам створює тег `v0.1.N` і GitHub Release
(архів коду і опис змін). `v0.1.0` — контрольна версія після аудиту.

## 7. Де що лежить

```
server/mds/services/   бізнес-логіка: bookings, orders, finance, analytics, stock, schedule, users, catalog,
                       reminders, gdrive, backup, journal, journal_feed, notifications, callbacks, bugreport
server/mds/api/        FastAPI: app.py, routers/*, schemas.py, deps.py
server/mds/bot/        Telegram: handlers.py (клієнти), staff.py (персонал), views.py (тексти/кнопки), runner.py
server/mds/web/static/ веб-панель: app.js, style.css, sw.js, index.html, іконки
server/migrations/     Alembic 0001–0011
server/tests/          114 тестів
apps/android, apps/windows   застосунки (після злиття PR)
docs/                  ARCHITECTURE, FINANCE, API, OPERATIONS, DEPLOY_RAILWAY, APPS, ROADMAP, AUDIT_v0.1, цей файл
CLAUDE.md              правила розробки; CHANGELOG.md — історія змін
```

Команди: `cd server && pip install -r requirements-dev.txt && python -m pytest`; `ruff check mds tests`;
`python -m mds init | run | serve | bot | migrate | backup | start`.
