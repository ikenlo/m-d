# План розвитку

## Етап 1 — робоча система ✅ (версія 0.1)
Сервер + БД, акаунти, календар, закриття замовлень, розрахунок часток, зміни і виплати,
фінансова панель, журнали, бекапи, Telegram-бот, веб-панель (PWA) для Android/Windows.

## Версія 0.2 ✅
Клієнтська база, SMS-розсилки (без реального надсилання), швидкодія, оновлений дизайн, UI-перевірка в CI.

## Версія 0.2.2 — правки директора (05.11.2026)

### Етап A — тексти й назви (швидко)
- [x] «Огляд»: прибрати підзаголовок «Фінанси салону: виручка, зарплати майстрів, витрати й прибуток».
- [x] Плитка «Витрати»: прибрати підпис «комунальні, генератор, реклама…»; плитки зробити компактнішими.
- [x] «Прогноз виручки»: пояснення («Прогноз — більше з двох…») дрібнішим шрифтом і ближче до цифр.
- [x] «Склад»: прибрати текст «Залишки матеріалів і фарб. Списуються автоматично…».
- [x] Перейменувати «Комунальні і генератор» → «Комунальні платежі».
- [x] Швидкий запис: прибрати кнопку «Інша послуга з прайсу — повна форма».
- [x] «Сьогодні» (майстер): кнопка «Запис» відкриває повну форму, а не швидкий запис.

### Етап B — баги свайпу й календаря
- [x] Свайп у стрічках/колодах: один рух — рівно одна сторінка (без «повзання» по трохи).
- [x] Свайп у кінці стрічки не повинен оновлювати сторінку (перехоплювати жест).
- [x] Якщо елементів 3 і менше — не робити слайдер, показати компактною сіткою.
- [x] Календар: прибрати смугу прокрутки, що з'являється під час гортання дат.

### Етап C — «Передзвонити» (заявки на дзвінок)
- [x] «Зателефонувати» — біла кнопка (набір номера), «Записати» — зелена (основна дія); «✕» — без запису.
- [x] Після «Передзвонили» кнопка змінюється на «Записати» — відкриває запис із даними клієнта.

### Етап D — швидкий запис: правила і час
- [x] Неробочий день — час не показуємо; запис у неробочий час заборонено.
- [x] Налаштування салону: «Дозволити запис у неробочий час» (вимкнено за замовчуванням).
- [x] Перевірка місць: 2 робочих місця — одночасно не більше 2 майстрів; усього майстрів — до 4.
      Майстер у свій вихідний може записати клієнта собі, лише якщо є вільне місце (на зміні 1 майстер).
- [x] Вільні вікна для будь-якої тривалості (45 хв, 1 год 23 хв…) — рахуються однаково правильно.
- [x] Рядок днів не гортається пальцем (фіксовані кнопки), плавні анімації замість «стрибків».

### Етап E — повна форма запису
- [x] Клієнт: ім'я і телефон.
- [x] Послуги як у швидкому записі: «Чоловіча» / «Жіноча»; чоловічі — один блок, жіночі — за категоріями.
- [x] Час: кнопки найближчих днів і вільних вікон; ручне введення часу сховане.
- [x] Без коментаря; ціна — як у прайсі; для послуг «від» — поле ціни.

### Етап F — клієнти і склад
- [x] Календар (телефон): рядок «N непідтверджених · M записів» під датою обрізається справа.
- [x] «Клієнти»: пошук — іконкою (відкривається поле за потреби).
- [x] «Клієнти»: лишити категорії «Новий», «Постійний», «Давно не був».
- [x] «Склад»: пошук — іконкою.

## Етап 2 — нативні застосунки Android і Windows
Рекомендовано **Flutter**: один код для Android і Windows, працює з тим самим REST API
(`docs/API.md`), бізнес-логіка лишається на сервері.

- [ ] Каркас Flutter-проєкту `apps/mds_app` (тема M&D, авторизація, збереження токена в захищеному сховищі).
- [ ] Майстер: «Сьогодні», закриття замовлення, зміна, заробіток (порт екранів PWA).
- [ ] Push-сповіщення (FCM) про нові записи — як доповнення до Telegram.
- [ ] Офлайн-черга закриття замовлень (з тим самим `idempotency_key` — сервер уже готовий).
- [ ] Windows: повний кабінет директора/адміністратора, друк/експорт звітів.
- [ ] Збірка: APK/AAB, MSIX-інсталятор; CI-збірка в GitHub Actions.

До готовності нативних версій PWA повністю закриває потреби обох платформ.
