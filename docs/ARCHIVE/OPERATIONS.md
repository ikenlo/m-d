# Встановлення та експлуатація

## 1. Де розмістити сервер

Сервер — одна програма (`python -m mds run`): API, веб-панель, Telegram-бот і бекапи.

| Варіант | Коли підходить |
|---|---|
| **Невеликий VPS** (рекомендовано), напр. 1 vCPU / 1 ГБ | Майстри відкривають застосунок з телефону звідусіль; HTTPS через Caddy |
| Комп'ютер директора в салоні (Windows) | Працює лише в мережі салону (або через Tailscale/VPN) |

Telegram-бот працює в режимі long polling — йому не потрібна публічна адреса.

## 2. Встановлення

```bash
git clone <репозиторій> && cd m-d/server
python -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env                 # за потреби
python -m mds init                   # міграції БД + перший директор
```

## 3. Запуск

```bash
export MDS_TELEGRAM_TOKEN=123456:ABC...   # Windows PowerShell: $env:MDS_TELEGRAM_TOKEN="..."
python -m mds run                          # http://0.0.0.0:8000
```

Окремо: `python -m mds serve` (без бота), `python -m mds bot` (лише бот).

### Автозапуск на Linux (systemd)

```ini
# /etc/systemd/system/mds.service
[Unit]
Description=MDS Connect
After=network.target

[Service]
WorkingDirectory=/opt/m-d/server
EnvironmentFile=/opt/m-d/server/.env
ExecStart=/opt/m-d/server/.venv/bin/python -m mds run --host 127.0.0.1
Restart=always

[Install]
WantedBy=multi-user.target
```

HTTPS (Caddy, сертифікат автоматично): `/etc/caddy/Caddyfile`
```
crm.ваш-домен.com.ua {
    reverse_proxy 127.0.0.1:8000
}
```

### Автозапуск на Windows
Планувальник завдань → «При вході в систему» → дія:
`C:\mds\server\.venv\Scripts\python.exe -m mds run`, робоча папка `C:\mds\server`.

## 4. Telegram-бот

1. У @BotFather: `/newbot` → отримати токен → `MDS_TELEGRAM_TOKEN`.
2. Там же `/setcommands`:
   ```
   start - Головне меню
   book - Записатися
   free - Вільний час
   my - Мої записи
   services - Послуги та ціни
   contacts - Контакти
   staff - Для майстрів
   ```
3. Меню клієнта: «📅 Записатися» (розділ → тип → вид → послуга → майстер з найближчим вільним часом →
   день → час за частинами дня), «⚡ Швидкий запис» (клієнт лишає номер — директору приходить заявка
   «передзвоніть», видно в боті та над календарем у панелі), «💅 Послуги та ціни», «🕐 Вільний час»
   (графік майстрів мінус уже зроблені записи), «📍 Контакти» (адреса/телефон/Instagram — *Налаштування → Telegram-бот*).
   Клієнт бачить лише ім'я майстра, без прізвища. Команда /my (свої записи) лишилась, але її немає в меню.
4. **Розділ «👩‍🎨 Для майстрів»:** спільний код персоналу (за замовчуванням `0000`, змінюється в
   *Налаштування → Telegram-бот*) → вибір себе → особистий PIN (задає директор у *Персонал → картка → PIN для Telegram-бота*).
   Невірний код — «Цей розділ не для вас». Після 5 невдалих спроб чат блокується на 15 хв; повідомлення з кодом і PIN бот видаляє.
   - Майстер: додати запис, мої записи (підтвердити, закрити замовлення, перенести, скасувати, «не прийшов»), заробіток, закрити зміну.
   - Директор: усі записи (перенести, видалити — як скасування з історією), додати запис будь-якому майстру,
     «📞 Передзвонити» (заявки швидкого запису), фінанси, підтвердження виплат.
   - Вхід через PIN автоматично підключає сповіщення для цього Telegram. Сесія діє 12 годин.
   - **Змініть код `0000` на власний** перед реальною роботою.
5. Сповіщення персоналу можна також підключити без PIN: у панелі *Профіль → Отримати код* → надіслати боту `/link КОД`.
   Директор отримує всі нові записи, зміни, скасування та звіти змін; майстер — події своїх записів.
6. **Непідтверджені записи.** Угорі на головній сторінці майстра (і над календарем у директора й адміністратора)
   блок «Непідтверджені записи» з кнопками:
   - **Підтвердити** — клієнт отримає «✅ Ваш запис підтверджено»;
   - **Інший час** — майстер обирає вільний час; запис переноситься, а клієнт отримує в боті
     «Майстер пропонує інший час» з кнопками «Підходить / Інший час / Скасувати»;
   - **Зайнято** — запис знімається, бот пише клієнту, що час зайнятий, і пропонує до 6 найближчих
     вільних часів кнопками (зайнятий час не пропонується); клієнт обирає — і запис створюється.
   Те саме доступне майстру в боті («Для майстрів» → «Мої записи»: «⛔ Зайнято», «🕐 Інший час»).
   Якщо клієнт записаний не через Telegram, програма підкаже його телефон, щоб зателефонувати.
7. Записи з бота мають статус «Очікує», доки адміністратор не підтвердить (або увімкніть
   *Налаштування → Записи з Telegram одразу підтверджені*). Клієнт отримує повідомлення про підтвердження.

## 5. Встановлення застосунку на телефон і комп'ютер (PWA)

- **Android (Chrome):** відкрити адресу сервера → меню ⋮ → «Додати на головний екран / Встановити застосунок».
- **Windows (Edge/Chrome):** відкрити адресу → значок «Встановити» в адресному рядку. З'явиться в меню «Пуск».

Для встановлення PWA на телефон потрібен HTTPS (див. Caddy вище); `localhost` працює й без нього.

## 6. Резервні копії

- Автоматично: при старті та кожні `MDS_BACKUP_INTERVAL_HOURS` (6) годин у `data/backups/`,
  зберігаються останні `MDS_BACKUP_KEEP` (40 ≈ 10 днів). Кожна копія перевіряється `PRAGMA integrity_check`.
- **Google Drive** (поза сервером): та сама копія одразу завантажується в папку
  «MDS Connect — резервні копії» на диску директора; там зберігаються останні `MDS_GDRIVE_KEEP` (180 ≈ 45 днів).
  Помилка завантаження → повідомлення директору в Telegram (не частіше разу на добу). Налаштування — нижче.
- Вручну: *Налаштування → Створити копію зараз / Зберегти на диск зараз* або `python -m mds backup`.

### Підключення Google Drive (один раз)

1. https://console.cloud.google.com → створіть проєкт (напр. «MDS Connect»).
2. *APIs & Services → Library* → увімкніть **Google Drive API**.
3. *APIs & Services → OAuth consent screen* (Google Auth Platform): тип **External**, назва «MDS Connect»,
   ваша пошта. У *Data access* додайте scope `.../auth/drive.file` (лише файли, створені програмою).
   В *Audience* натисніть **Publish app** (статус «In production»): інакше Google відкликає доступ через 7 днів.
   Для `drive.file` перевірка Google не потрібна; при вході може з'явитись попередження «неперевірений застосунок» —
   *Додатково → Перейти до MDS Connect*.
4. *Clients → Create client* → тип **Web application**; *Authorized redirect URIs*:
   `https://m-d-production.up.railway.app/api/gdrive/callback`.
5. Скопіюйте *Client ID* і *Client secret* у змінні Railway: `MDS_GDRIVE_CLIENT_ID`, `MDS_GDRIVE_CLIENT_SECRET`.
6. Директор: *Налаштування → Резервні копії → Підключити Google Drive* → увійти тим Google-акаунтом,
   де мають лежати копії → дозволити. Готово: далі все працює саме.

Доступ зберігається у `data/gdrive.json` (лише на сервері, не в API). *Відключити* — забуває доступ,
уже збережені на диску копії лишаються.
- Відновлення: зупинити сервер → скопіювати потрібний `mds-YYYYMMDD-HHMMSS.db` як `data/mds.db` → запустити.
- PostgreSQL: замість вбудованих бекапів — `pg_dump` за розкладом.

Також зберігайте `data/secret.key` (без нього всі користувачі просто увійдуть заново — дані не втрачаються).

## 7. Оновлення

```bash
git pull
pip install -r requirements.txt
python -m mds migrate      # застосувати нові міграції (до запуску!)
# перезапустити сервіс
```
Перед оновленням зробіть резервну копію.

## Демо-дані (лише тестове середовище)

- `MDS_DEMO_FOP1=yes` у змінних Railway (або `python -m mds demo-fop1`) → після старту в окремому процесі:
  резервна копія, видалення лише демо-позначених даних, сценарій «ФОП 1 група» (одна власниця, ~1,1 млн ₴/рік,
  2025 р. і 2026 р. до вчора). Після заповнення змінну видалити; повторний запуск нічого не дублює.
- Демо-дані: логіни `demo_*`, «(демо)» в іменах, нотатках і описах, телефони клієнтів +38067999xxxx.
- Перед відкриттям салону — чиста база (послуги перенести), демо-дані не мають потрапити в робочий облік.

## Очищення робочих даних (лише за рішенням директора)

- `python -m mds wipe-data --yes` або змінна Railway `MDS_WIPE_DATA=<мітка>` (напр. дата) → під час старту:
  резервна копія бази, потім видалення записів, замовлень, клієнтів, графіка, змін, виплат, витрат, складу,
  податків і зарплати, журналів, сповіщень і демо-акаунтів `demo_*`.
- Лишаються: акаунти співробітників, послуги (прайс), налаштування.
- З тією самою міткою повторно не виконується (мітка зберігається в налаштуваннях). Після очищення змінну видалити.
- Повернути дані можна лише з резервної копії (`backups/` на диску сервера).

## Двофакторний вхід (код у Telegram)

- Для ролей з «Налаштування → Безпека входу» (за замовчуванням — директор) після пароля на новому пристрої бот
  надсилає 6-значний код (5 хв, 5 спроб). Пристрій можна запам'ятати на 30 днів; зміна пароля забуває всі пристрої.
- Працює лише якщо в людини підключено Telegram; список пристроїв і «Забути всі» — у «Профілі».
- Якщо бот/Telegram недоступні і увійти неможливо: змінна Railway `MDS_TWOFA_DISABLED=1` тимчасово вимикає код.
  Після відновлення — видалити змінну.

## SMS / Viber клієнтам (TurboSMS)

- Для повідомлень клієнтам без Telegram (напр. «запис зсунуто на 15 хв»). Реєстрація на turbosms.ua, у кабінеті —
  ім'я відправника (альфа-ім'я) і API-токен. Змінні Railway: `MDS_TURBOSMS_TOKEN`, `MDS_TURBOSMS_SENDER`.
  Потім «Налаштування → Захист онлайн-запису → SMS / Viber клієнтам». Надсилається Viber, хто не має — SMS (платно за тарифом TurboSMS).
- Без ключа нічого не надсилається: після зсуву програма показує, кому подзвонити.
- Розділ «SMS-розсилки» (директор): баланс, витрати (вартість розсилки → «Витрати», категорія «Реклама»),
  одноразові розсилки за сегментами лише клієнтам зі згодою, аналіз найкращого часу, автопривітання з ДН і
  нагадування про повторний візит (налаштування `sms_price`, `sms_auto_birthday`, `sms_auto_return`, `sms_auto_hour`).
- Усі SMS проходять через чергу `sms_messages`; фоновий цикл (раз на 5 хв) надсилає її й оновлює статуси доставки.
  Помилки TurboSMS (таймаут 10 с) записуються в статус повідомлення і не зупиняють роботу салону.
